# 반쵸 타코야키 포장마차 — 데모 개발 명세서

> HTML5 단일 페이지 데모. AI 코딩 도구에 이 문서를 그대로 전달해 티켓 순서대로 구현한다.
> 수치는 전부 초기 가정값이며, 플레이테스트 후 갱신한다.

---

## 0. 이 데모가 증명할 것

**주장:** 데이브 더 다이버의 핵심은 "다음 날이 기대되는 하루"이고, 그 기대는 발견에서 온다. 바다가 없는 반쵸 더 셰프에서는 발견의 축을 "레시피의 빈칸"으로 옮긴다.

**검증할 가설 3개**
1. 레시피 밖 재료를 넣는 실험이 다음 날 장보기를 기대하게 만든다.
2. 힌트가 단계적으로 흐려져도(지시 → 방향 → 없음) 플레이어는 손님 반응을 단서로 스스로 조합을 찾는다.
3. 새 재료가 굽는 손맛까지 바꾸면, 새로움이 "맛"과 "손" 두 층에서 동시에 공급된다.

**발견의 3단계 (설계 기준)**
| 단계 | 정의 | 데모 위치 |
|---|---|---|
| 지시 | 누가 정답을 말해줌 | 1일차 참새 |
| 가설 | 단서를 보고 골라서 넣음 | 2일차 까마귀 |
| 발견 | 의도보다 결과가 더 나옴 (숨은 요리) | 2~3일차 |

## 1. 하루 흐름 (상태 머신)

코드보다 이 흐름을 먼저 고정한다. 모든 화면 전환은 이 상태 사이에서만 일어난다.

```
LETTER → SHOP → PREP → OPEN_BELL → ORDER → COOK → REACTION
                                      ↑                  │
                                      └── 다음 주문 ──────┘
                                                         ↓
                                              DAY_END_TALK → GIFT_CHOICE → (다음 날 LETTER | DEMO_END)
```

| 상태 | 내용 | 비고 |
|---|---|---|
| LETTER | 편지 읽기 (비주얼 노벨 대화창) | 1일차: 운영 부탁 + 준비물 / 2·3일차: 일정액 송금 |
| SHOP | 재료 구매 | **1일차는 건너뜀** (재료 지급됨) |
| PREP | 포장마차 세팅 | 클릭 한 번. 새 조작 없음 |
| OPEN_BELL | 종 "띵띵" 소리 → 영업 시작 | 소리가 먼저, 손님은 나중 |
| ORDER | 손님 등장 + 주문 | 목소리 먼저, 모습 나중 |
| COOK | 기존 굽기 모듈 실행 | 아래 4장 인터페이스 |
| REACTION | 단계별 반응 + 결제/선물 | 아래 5장 규칙 |
| DAY_END_TALK | 손님이 내일 힌트를 흘림 | 힌트 곡선 6장 |
| GIFT_CHOICE | 선물을 팔지 / 남길지 | 7장 |
| DEMO_END | 3일차 종료 후 결과 화면 | 9장 |

**반쵸 대사 규칙:** 반쵸는 "…", "음.", "?" 같은 짧은 반응과 아이콘 표정만 쓴다. 설명은 편지와 손님이 한다.

## 2. 재료 데이터

각 재료는 **맛 태그**와 **굽기 보정값**을 가진다. 새 재료 = 새 맛 + 새 손맛.

```json
[
  {"id":"octopus","name":"문어","price":0,"tags":["쫄깃함","짭조름"],"pourTarget":0,"flipWindow":1.0,"note":"기본 재료"},
  {"id":"pinenut","name":"잣","price":180,"tags":["고소함"],"pourTarget":0,"flipWindow":0.6,"note":"빨리 탄다 → 뒤집기 타이밍 짧아짐"},
  {"id":"pear","name":"배","price":150,"tags":["단맛","시원함"],"pourTarget":-0.15,"flipWindow":1.0,"note":"물기 많음 → 반죽을 덜 부어야 함"},
  {"id":"apple","name":"사과","price":120,"tags":["단맛","새콤함"],"pourTarget":-0.05,"flipWindow":1.0},
  {"id":"radish","name":"무","price":80,"tags":["시원함"],"pourTarget":-0.15,"flipWindow":1.0},
  {"id":"shrimp","name":"새우","price":200,"tags":["감칠맛","쫄깃함"],"pourTarget":0,"flipWindow":0.8},
  {"id":"scallion","name":"파","price":60,"tags":["향긋함","감칠맛"],"pourTarget":0,"flipWindow":1.0},
  {"id":"ginger","name":"생강절임","price":80,"tags":["새콤함","매콤함"],"pourTarget":0,"flipWindow":1.0}
]
```

- **속재료 슬롯 2칸.** 문어가 기본으로 1칸을 쓰며, 빼고 다른 재료로 바꿀 수 있다.
- 재료 1개 = 1판(6알) 분량.
- `pourTarget`: 반죽 "찍" 목표 지점 이동 비율. `flipWindow`: 뒤집기 성공 판정 폭 배율.
- 두 재료의 보정값은 곱/합으로 누적한다 (pourTarget 합, flipWindow 곱).

## 3. 손님 데이터

```json
[
  {"id":"sparrow","day":1,"name":"참새","likes":["고소함","짭조름"],"dislikes":["매콤함"],"orders":2,"pays":0,"gift":"pinenut_pack"},
  {"id":"crow_a","day":2,"name":"까마귀","likes":["단맛","시원함"],"dislikes":["매콤함"],"orders":1,"pays":0.5,"gift":"shiny_button"},
  {"id":"crow_b","day":2,"name":"까마귀","likes":["단맛","시원함"],"dislikes":["매콤함"],"orders":1,"pays":0.5,"gift":"shiny_button"},
  {"id":"tanuki","day":3,"name":"너구리","likes":["감칠맛","짭조름"],"dislikes":["단맛"],"orders":2,"pays":0.3,"gift":null}
]
```

- `orders`: 한 손님이 몇 판 주문하는지. 2판이면 첫 판 반응을 단서로 두 번째 판을 고칠 수 있다.
- `pays`: 돈을 낼 확률. 요괴는 대개 돈 대신 선물을 준다.
- **2일차 까마귀는 한 마리씩 차례로 온다.** 동시 응대 없음.

## 4. 굽기 모듈 인터페이스

기존 굽기 파트는 "재료를 받고 결과를 돌려주는 부품"으로 감싼다. 내부 구현은 건드리지 않는다.

```js
// 입력
startCooking({
  ingredients: ["octopus", "pinenut"],
  modifiers: { pourTarget: 0, flipWindow: 0.6 }   // 2장 규칙으로 계산해서 전달
})
// 출력 (Promise)
→ { craft: 0.0~1.0,          // 6알 평균 손 점수 (반죽 정확도 + 뒤집기 정확도)
    perBall: [ {pour:0.9, flip:0.7}, ... ],
    ingredients: ["octopus", "pinenut"] }
```

- 반죽 "탁탁탁 찍" 목표 지점과 뒤집기 "쉬릭쉬릭" 판정 폭이 `modifiers`에 따라 실제로 달라져야 한다.
- 실패는 코믹 연출(반죽 넘침, 덜 참, 탄 알)로 보여주되, **판은 항상 완성**된다. 바닥은 낮게.

## 5. 반응 규칙 (결과창이 아니라 단서)

### 5.1 만족도 계산
```
match  = (손님 likes 중 판에 있는 태그 수 − dislikes 중 판에 있는 태그 수) / likes 개수   // −1 ~ 1, 0 미만은 0
satisfaction = 0.4 × craft + 0.6 × match
숨은 요리 성립 시 satisfaction += 0.2 (최대 1.0)
```

### 5.2 반응 단계
| 만족도 | 반응 | 반드시 포함할 정보 |
|---|---|---|
| < 0.3 | 코믹한 실패 반응 | 싫어하는 태그가 있으면 그것을 암시 ("으, 이 톡 쏘는 건 뭐야") |
| 0.3 ~ 0.6 | "괜찮은데 뭔가 아쉬워" | **빠진 likes 태그 하나를 모호하게 언급** ("단 게 좀 아쉽네") |
| 0.6 ~ 0.85 | "맛있다" | 없음 |
| ≥ 0.85 | "최고다" | 없음 |
| 숨은 요리 | 놀람 반응 + 요리 이름 공개 | "이건… 처음 먹어보는 맛인데?" |

- 0.3~0.6 구간 반응은 반드시 **다음 판단의 단서**가 되어야 한다. 이게 이 데모의 핵심 장치.

### 5.3 결제
```
가격 = 300 × (0.5 + satisfaction)      // 숨은 요리면 × 1.5
pays 확률로 돈 지불, 아니면 선물만
```

## 6. 힌트 곡선

| 일차 | 힌트 방식 | 내용 |
|---|---|---|
| 1일차 | **지시** | 참새가 첫 판(문어만)을 먹고 "잣 넣으면 더 맛있을 것 같은데~"라고 직접 요청. 잣은 지급 재료에 이미 있지만 레시피엔 없음 |
| 1일차 밤 | 방향 | 참새: "내일은 까마귀들이 올 것 같은데. 걔들은 **달고 시원한 걸** 좋아하더라~" |
| 2일차 | **가설** | 장보기 후보: 배(단+시원), 사과(단+새콤), 무(시원). 돈 제한으로 다 못 삼 |
| 2일차 밤 | 없음 | 까마귀: "내일 오는 녀석은 입맛이 까다로워" 정도만 |
| 3일차 | **스스로** | 너구리는 취향을 말하지 않음. 첫 판 반응(5.2)이 유일한 단서 |

## 7. 경제와 선물

- **편지 일정액:** 매일 아침 500. 실패해도 다음 날 장은 볼 수 있다.
- 1일차는 문어, 잣 지급. SHOP 없음.
- 2일차 시작 자금 ≈ 500 + 1일차 수입. 까마귀 2판 분량 + 실험용 1개 정도가 가능한 수준.

| 선물 | 출처 | 팔기 | 남기기 |
|---|---|---|---|
| 잣 꾸러미 (2판분) | 참새 | 300 | 재료로 사용 → 2일차 숨은 요리의 열쇠 |
| 반짝이 단추 | 까마귀 | 400 | 쓸모 없음 (대비용) |

- **잣 꾸러미의 선택이 핵심.** 팔면 2일차 장보기가 넉넉해지고, 남기면 숨은 요리 "배잣 타코야키"를 만들 수 있다. 어느 쪽이 정답인지 알려주지 않는다.

## 8. 숨은 요리

```json
[
  {"id":"pear_pinenut","name":"배잣 타코야키","requires":["pear","pinenut"],"minCraft":0.6,"discoverLine":"달고 시원한데… 고소한 게 끝에 남아!"},
  {"id":"shrimp_scallion","name":"새우파 타코야키","requires":["shrimp","scallion"],"minCraft":0.6,"discoverLine":"이 진한 맛은 뭐지?"},
  {"id":"octopus_ginger","name":"생강 타코야키","requires":["octopus","ginger"],"minCraft":0.5,"discoverLine":"톡 쏘는데 묘하게 당기네"}
]
```

- 숨은 요리는 **힌트로 직접 알려주지 않는다.** 힌트를 따라가다 의도 너머에서 만나는 것.
- 발견 시 요리 이름 카드 연출 + 도감 기록.

## 9. 3일차 마무리와 결과 화면

1. 너구리 응대 종료 후, 편지 보낸 장인의 새 편지 도착: "자네만의 타코야키를 보여주게. 내일은 내가 직접 가지." → "다음 날" 예고로 데모 종료.
2. 결과 화면에 표시:
   - 발견한 숨은 요리 / 전체
   - 레시피 밖 재료를 넣은 횟수 (힌트 있을 때 / 없을 때 구분)
   - 잣 꾸러미를 팔았는지 남겼는지
   - 일차별 평균 craft, 평균 만족도
3. "로그 내보내기" 버튼으로 아래 10장 로그를 JSON 다운로드.

## 10. 플레이 로그 (주장의 증거)

모든 이벤트를 배열에 쌓는다.

```json
{"t":"2026-10-10T12:00:00","day":2,"event":"buy","item":"pear","qty":2,"money":120}
{"t":"...","day":3,"event":"cook","ingredients":["octopus","shrimp"],"craft":0.72,"offRecipe":true,"hintGiven":false}
{"t":"...","day":3,"event":"reaction","customer":"tanuki","satisfaction":0.55,"tier":"아쉬움","clueTag":"감칠맛"}
{"t":"...","day":1,"event":"gift_choice","gift":"pinenut_pack","choice":"keep"}
{"t":"...","day":2,"event":"hidden_recipe","id":"pear_pinenut"}
```

**핵심 지표**
- 3일차에 힌트 없이 레시피 밖 재료를 넣은 비율
- 3일차 두 번째 판에서 첫 판 단서 태그를 반영한 비율
- 잣 꾸러미를 남긴 비율과 숨은 요리 발견률

## 11. 구현 티켓

> 규칙: 티켓 하나 끝나면 멈추고 확인받는다. 기획이 애매하면 추측하지 말고 질문한다. 완료 조건은 화면에서 직접 확인 가능한 문장으로 쓴다.

| # | 티켓 | 완료 조건 |
|---|---|---|
| 1 | 상태 머신 골격 | 버튼으로 LETTER → … → DEMO_END까지 3일을 빈 화면으로 순회할 수 있다 |
| 2 | 대화창 엔진 (데이터 구동) | `dialogue.json`의 대사가 클릭할 때마다 넘어가고, 화자 아이콘이 바뀐다 |
| 3 | 배경 레이어 | 장면마다 배경 이미지가 바뀌고, 밤에는 어둡게 덮인다 |
| 4 | 편지 화면 | 1일차 편지(운영 부탁 + 준비물), 2·3일차 편지(+500)가 표시되고 돈이 늘어난다 |
| 5 | 굽기 모듈 연결 | 선택한 재료와 보정값이 굽기에 전달되고, craft 결과가 돌아온다 |
| 6 | 재료 보정 반영 | 배를 넣으면 반죽 목표 지점이, 잣을 넣으면 뒤집기 판정 폭이 눈에 띄게 달라진다 |
| 7 | 손님 등장 연출 | 종소리 → 목소리 → 모습 순서로 손님이 등장한다 |
| 8 | 반응 규칙 | 만족도 구간별 반응이 나오고, 0.3~0.6 구간에서 빠진 태그가 대사로 언급된다 |
| 9 | 장보기 | 2일차부터 돈 한도 안에서 재료를 살 수 있고, 돈이 부족하면 못 산다 |
| 10 | 선물 선택 | 잣 꾸러미를 팔거나 남길 수 있고, 남기면 다음 날 재료 목록에 나온다 |
| 11 | 숨은 요리 | 배+잣을 craft 0.6 이상으로 구우면 이름 카드가 뜨고 가격이 1.5배가 된다 |
| 12 | 3일차 마무리 + 결과 화면 | 장인의 편지 후 결과 화면에 지표 4개가 보인다 |
| 13 | 로그 내보내기 | 버튼을 누르면 이벤트 로그 JSON이 다운로드된다 |
| 14 | 소리·연출 다듬기 | 반죽 "탁탁탁 찍", 뒤집기 "쉬릭", 종 "띵띵"이 각각 들린다 |

**순서 원칙:** 발견 루프(1~13) 먼저, 손맛 연출(14)은 마지막.

## 12. 문서에만 남길 것 (데모 범위 밖)

- 요일별 손님 스케줄과 예측 준비
- 여러 손님 동시 응대
- 재료 조합이 바닥나지 않게 하는 장기 구조: 태그 규칙 × 매일 바뀌는 손님 수요로 같은 재료도 새 답이 된다
- 캐릭터 설정 상세, 장인 서사
